# LTM PMBus Tool

Приложение на Tkinter для чтения телеметрии, просмотра статусов и настройки модулей питания LTM по PMBus/I2C.

Текущая версия разработки – V4.8. Профили устройств и USB-адаптеры имеют разную степень аппаратной проверки. Перед подключением ознакомьтесь с таблицами ниже.

## Возможности

- Отдельные карты регистров LTM4673, LTM4677 и LTM4678.
- Телеметрия и периодический мониторинг с учётом возможностей профиля.
- Чтение и запись поддерживаемых настроек.
- Явные управляющие действия, включая CLEAR_FAULTS и сохранение или восстановление NVM.
- Экспорт и импорт доступных регистров в CSV.
- Проверка допустимости обычного чтения и записи по профилю.
- Проверка зависимостей при запуске с диагностикой в консоли.

Открытие вкладки устройства автоматически запускает Read All. Для нового устройства или непроверенного профиля сначала используйте ограниченный диагностический тест без GUI.

## Профили устройств и результаты проверки

| Модель | Страниц | Ожидаемая экспонента L16 | Состояние проверки |
|---|---|---|---|
| LTM4673 | 4 | -13 | Чтение байта и слова, PAGE, телеметрия и статусы проверены через CH341T и FT232H |
| LTM4677 | 2 | -12 | Ограниченный набор чтений и PAGE проверены через CH341T после явной очистки ошибок |
| LTM4678 | 2 | -12 | Профиль реализован, аппаратная проверка ожидается |

Профиль определяется по `MFR_SPECIAL_ID & 0xFFF0`.

| Модель | Зарегистрированные семейства ID |
|---|---|
| LTM4673 | `0x448X`, `0x023X` |
| LTM4677 | `0x47BX` |
| LTM4678 | `0x410X` |

Инженерный образец LTM4673 с ID `0x0236` поддерживается намеренно. 

LTM4675 в текущий набор профилей не входит.

Успешная проверка обмена не подтверждает все регистры, запись настроек, операции NVM или исправность силовой части.

Испытания имеющегося модуля LTM4677 приостановлены из-за подозрения на аппаратную неисправность. После явной очистки тест обмена завершился с нулевым CML, но причина большого показания тока на одном выключенном канале не установлена.

## USB-адаптеры и номера шин

| Номер шины | Интерфейс | Python-пакет | Текущее состояние |
|---|---|---|---|
| 0–99 | Системная I2C | `smbus2` или `smbus` | Не реализована в текущей фабрике шин |
| 100–199 | CH341T и совместимые CH341 в режиме I2C | `pyusb` | Проверено на CH341T |
| 200–299 | FTDI MPSSE | `pyftdi` | Проверено на FT232H с PyFtdi 0.57.2 |
| 300–399 | CP2112 | `hidapi` | Драйвер присутствует, аппаратная отладка ожидается |

Шина `100` выбирает CH341 с индексом 0. Шина `200` выбирает FTDI с индексом 0. Индексы соответствуют порядку обнаружения, а не постоянным аппаратным идентификаторам.

FTDI-драйвер также обнаруживает FT2232H и FT4232H и открывает интерфейс 1. Эти варианты в проекте аппаратно не проверены.

### Ограничения CH341

- USB-ошибки и неполные ответы передаются исключениями.
- Промежуточные байты чтения подтверждаются ACK, последний завершается NACK.
- Проверка ACK ведомого в этой реализации отсутствует.
- Успешная USB-транзакция не доказывает принятие записи микросхемой.
- Чтение фиксированного блока I2C не является SMBus Block Read.
- PEC не реализован.

### Особенности FTDI

Формирование I2C-транзакций выполняет PyFtdi. Обёртка передаёт ошибки обмена вместо подстановки `0xFF` или `0xFFFF`.

Начальная частота шины – 100 кГц. Слова передаются младшим байтом вперёд.

Clock stretching в текущей конфигурации выключен. Для его включения в PyFtdi требуется соответствующее дополнительное соединение и отдельная проверка.

Методы фиксированного блочного обмена не реализуют SMBus Block Read с байтом количества. PEC в обёртке не реализован.

## Подключение оборудования

Отключайте питание перед изменением соединений. Для первых проверок используйте один активный USB-адаптер на шине.

Типовое подключение FT232H:

| Сигнал FT232H | Соединение |
|---|---|
| ADBUS0 / D0 | SCL |
| ADBUS1 / D1 | Выход SDA, объединить с D2 и SDA устройства |
| ADBUS2 / D2 | Вход SDA, объединить с D1 и SDA устройства |
| GND | Общий провод устройства |

Проверьте схему модуля. Некоторые платы уже объединяют сигналы SDA или содержат согласование уровней.

SCL и SDA требуют подтяжек к напряжению, допустимому для адаптера и устройства. В проверенной конфигурации использовался интерфейс 3,3 В. Сопротивление выбирается с учётом ёмкости шины, скорости и уже установленных резисторов; 2,2 кОм не является универсальным требованием.

Не соединяйте выход питания адаптера с отдельно запитанным устройством без проверки схемы питания.

## Зависимости

Используйте Python 3 с Tkinter. В прежних инструкциях установка ориентировалась на Python 3.13; полная матрица совместимости с минимальными версиями пока не определена.

Python-пакеты:

```bash
python -m pip install smbus2 pyusb pyftdi hidapi
```

Модуль `hid`, используемый драйвером CP2112, предоставляется пакетом `hidapi`. Установка другого пакета с именем `hid` может вызвать конфликт.

Tkinter устанавливается средствами ОС или установщика Python, а не через pip. Для CH341 и FTDI также нужна системная библиотека libusb-1.0.

Debian или Ubuntu:

```bash
sudo apt install python3-venv python3-tk libusb-1.0-0
```

openSUSE с Python 3.13:

```bash
sudo zypper install python313-tk libusb-1_0-0
```

Названия пакетов должны соответствовать используемому интерпретатору и дистрибутиву.

### Проверка при запуске

`main.py` вызывает `dep_check.py` до импорта приложения.

Проверка сообщает в консоли об отсутствующих или неработающих модулях, показывает путь к Python и рекомендации по установке. При проблемах программа завершается с ненулевым кодом.

Сейчас проверяются:

- Tkinter и ttk.
- PyUSB.
- PyFtdi.
- HIDAPI.
- Модули совместимости SMBus в аппаратном режиме.
- Backend libusb в аппаратном режиме.

Драйверы пока импортируются безусловно. Поэтому их Python-зависимости проверяются даже при использовании одного адаптера.

Проверка ничего не устанавливает, не открывает адаптеры и не проверяет USB-права. Её успешное завершение не подтверждает доступность оборудования.

## Установка и запуск

Создайте отдельное окружение из каталога проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install smbus2 pyusb pyftdi hidapi
python main.py
```

Запускайте приложение из терминала, чтобы видеть диагностику старта.

Не используйте `sudo` как обычный способ запуска. Настройте USB-права для текущего пользователя.

### USB-права в Linux

На настольных системах с systemd-logind правило udev может предоставить доступ активному локальному пользователю. Пример для CH341 с USB ID `1a86:5512`:

```text
SUBSYSTEM=="usb", ATTR{idVendor}=="1a86", ATTR{idProduct}=="5512", TAG+="uaccess"
```

Поместите правило, например, в `/etc/udev/rules.d/70-ltm-pmbus.rules`, затем перечитайте правила и переподключите адаптер:

```bash
sudo udevadm control --reload-rules
```

Для других адаптеров используйте их фактические USB ID. На системах без локальной графической сессии могут потребоваться групповые права вместо `uaccess`.

Если драйвер ядра мешает захватить интерфейс, проверьте привязку конкретного устройства. Глобальная выгрузка `ftdi_sio` и `usbserial` не является обязательным шагом запуска и может нарушить работу других устройств.

## Доступ к регистрам и безопасность

Идентификация выполняется чтением слова `MFR_SPECIAL_ID` по адресу `0xE7`. Запись PAGE проверяется обратным чтением.

Обычный доступ ограничен выбранным профилем:

- Перед обменом проверяются наличие команды и размер регистра.
- Команды со специальным протоколом исключены из обычного опроса.
- Статусы запрещены для общей записи и восстановления дампа.
- Send Byte-действия отделены от записи настроек.
- CLEAR_FAULTS не выполняется автоматически при подключении.
- Зарезервированные регистры LTM4673 `0xB5` и `0xBC` исключены из обычного доступа.

Read Dump читает не все документированные адреса, а только разрешённые текущей политикой обычного доступа регистры.

Write Dump не является побайтовым клонированием устройства. Записи CSV не могут отменить запреты PMBus-слоя. Перед записью проверьте модель, адрес и страницу.

Store NVM и Restore NVM выполняются явно. Для диагностики ошибок чтения эти операции не нужны.

## Отображение статусов

Для LTM4673 реализованы проверенные расшифровки стандартных статусов, `STATUS_MFR_SPECIFIC`, `MFR_PADS` и `MFR_COMMON`.

`STATUS_MFR_SPECIFIC` имеет адрес `0x80`. Внутреннее имя совместимости `STATUS_MFR` не обозначает отдельную команду.

У LTM4673 значение `STATUS_MFR_SPECIFIC=0x18` означает достижение цели сервосистемы и подключение DAC. Это информационные состояния, а не аварии.

`MFR_PADS` и `MFR_COMMON` отображаются в Global Status. Установленные информационные биты сами по себе не создают признак аварии.

После Read All статусы обновляются после остальных групп регистров, чтобы показать CML, возникший во время опроса.

Для LTM4677 и LTM4678 пока используется серое отображение сырых значений там, где модельная расшифровка не включена. В текущей реализации это затрагивает и стандартные строки статусов.

Биты CML не маскируются. Ошибка чтения статуса не должна отображаться как OK.

## Форматы данных

| Формат | Значение |
|---|---|
| L11 | Знаковая 11-битная мантисса, умноженная на два в степени знаковой 5-битной экспоненты |
| L16 | Беззнаковое 16-битное значение, умноженное на два в степени экспоненты из VOUT_MODE |
| BYTE / RAW | Немасштабированные значения командных полей и битов статуса |
| Модельные форматы | Применяются только там, где явно заданы в профиле |

Экспонента выходного напряжения не управляет преобразованием тока L11. Экспоненту L16 `-12` у LTM4677 нельзя применять к `READ_IOUT`.

## Симулятор

В точке входа сохранены оба флага:

```bash
python main.py --sim
python main.py --demo
```

Режим симуляции требует доработки. Одной подмены SMBus недостаточно для восстановления ветки сканера и согласования симулируемых ID, PAGE и VOUT_MODE с текущими профилями.

Симулятор пока нельзя считать проверенным способом тестирования актуальных карт устройств.
