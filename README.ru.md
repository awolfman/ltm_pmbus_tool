# LTM PMBus Tool (V4.8+)

Приложение на Tkinter для чтения телеметрии, регистров статуса и настройки силовых модулей по протоколу PMBus/I2C.

Текущая рабочая версия отражает последние обновления архитектуры, профилей устройств и статусов аппаратной валидации.

## Возможности

- **Специфичные для моделей карты регистров и интерфейсы**: Полная поддержка LTM4673, LTM4677 и LTM4678 с визуальным управлением конфигурацией, разделенным на 3–5 целевых вкладок.
- **Продвинутая телеметрия и мониторинг**: Периодический опрос в соответствии с выбранным профилем с автоматическим обновлением таблиц статуса после опроса регистров.
- **Безопасная архитектура конфигурации**: Проверка базовых линий (baselines), предварительный просмотр изменений (preview), валидация точного соответствия считанных RAW-значений и защита от некорректных конфигураций.
- **Явные управляющие действия**: Целевое выполнение `CLEAR_FAULTS`, операций сохранения/восстановления энергонезависимой памяти (NVM) и специализированные пресеты для `OPERATION` и `ON_OFF_CONFIG`.
- **Безопасный обмен данными через CSV**: Экспорт и импорт карт регистров со строгой проверкой контрольных сумм по алгоритму SHA-256 и валидацией записей перед записью в устройство.
- **Надежное восстановление при отключении транспорта**: Корректная обработка обрывов связи во время сканирования, выполнения Read All и опроса телеметрии. Автоматически останавливает циклы, помечает вкладки как отключенные, а данные — как устаревшие.
- **Диагностическое логирование**: Предварительные проверки зависимостей перед запуском GUI и диагностика в консоли в реальном времени.

Открытие вкладки устройства автоматически запускает транзакцию `Read All`. Для неверифицированных профилей или новых модулей рекомендуется выполнить ограниченный диагностический тест перед работой через графический интерфейс.

| Модель | Каналы | Рабочие лимиты | Сопоставление профилей (`MFR_SPECIAL_ID & 0xFFF0`) | Текущий статус валидации |
| :--- | :---: | :--- | :--- | :--- |
| **LTM4673** | 4 | VIN: 4.5–16V<br>VOUT: 0.5–5.5V<br>IOUT max: 8A | `0x448X`, `0x023X` (Инженерный семпл `0x0236` поддерживается явно) | Побайтовое/пословное чтение, выбор PAGE, телеметрия и статусы протестированы с CH341T и FT232H. Контекстно-зависимые кодировки OPERATION в данный момент заблокированы. |
| **LTM4677** | 2 | VIN: 4.5–16V<br>VOUT: 0.5–1.8V<br>IOUT max: 18A | `0x47BX` | **Тестирование силовой части приостановлено.** Обмен данными успешно завершился с нулевым CML после явного сброса ошибок, но неожиданные показания тока на одном из отключенных каналов остаются на стадии анализа. |
| **LTM4678** | 2 | VIN: 4.5–16V<br>VOUT: 0.5–3.4V<br>IOUT max: 25A | `0x410X` | Полностью проверен на реальном железе: обнаружение, запуск, инициализация GUI, запись `VOUT_COMMAND`, мониторинг и сценарии переподключения USB с CH341T и FT232H. |

## USB-адаптеры и номера шин

| Диапазон номеров шин | Бэкенд / Транспорт | Пакет Python | Текущее состояние разработки и валидации |
| :--- | :--- | :--- | :--- |
| **0 – 99** | Нативный системный I2C | `smbus2` или `smbus` | Не реализовано в текущей фабрике шин (bus factory). |
| **100 – 199** | CH341T / Совместимое устройство CH341 | `pyusb` | Протестировано на железе: обнаружение, телеметрия и сценарии восстановления связи (Шина `100` выбирает CH341 с индексом 0). |
| **200 – 299** | FTDI MPSSE (целевой FT232H) | `pyftdi` | Протестировано на железе с FT232H и PyFtdi 0.57.2, включая циклы отключения (Шина `200` выбирает FTDI с индексом 0). |
| **300 – 399** | CP2112 | `hidapi` | Драйвер транспорта реализован; аппаратная валидация ожидает завершения. |

*Индексы адаптеров отражают динамические позиции перечисления при обнаружении, а не постоянные аппаратные идентификаторы. Процедуры повторного подключения не обеспечивают безопасное автоматическое переназначение при изменении порядка перечисления устройств.*

### Ограничения и поведение бэкенда CH341
- Драйвер вызывает явные исключения при сбоях USB-транзакций и неполных ответах пакетов.
- Промежуточные байты чтения подтверждаются (ACK); финальный байт завершается сигналом NACK.
- Наличие ACK от ведомого устройства (Slave ACK) данной реализацией не проверяется; успешное завершение USB-передачи не гарантирует, что целевой модуль принял запись.
- Чтение блоков I2C фиксированной длины представляет собой стандартные пересылки, а не транзакции SMBus Block Read. PEC не реализован.

### Поведение бэкенда FTDI
- Обертка транслирует низкоуровневые ошибки транспорта PyFtdi вместо возврата фиктивных маркеров сбоя `0xFF` или `0xFFFF`.
- Начальная частота шины установлена на 100 кГц, передача слов использует порядок байтов little-endian.
- Растягивание тактового сигнала (Clock stretching) по умолчанию отключено. Его включение требует соответствующей доработки схемы соединений и отдельной программной валидации.
- Процедура перечисления FTDI очищает кэш обнаружения PyFtdi перед выводом списка устройств для предотвращения зависших подключений. Старые объекты транспорта должны освобождаться вручную перед созданием новой сессии.

## Рабочий процесс редактора конфигурации (Config)

Интерфейс конфигурации (`gui/config_notebook.py`) опирается на строгие правила валидации для защиты оборудования:

1. **Операция чтения (Синяя стрелка)**: Считывает значение одного регистра из устройства и обновляет поле ввода.
2. **Операция записи (Зеленая стрелка)**: Выполняет запись конфигурации после явного подтверждения пользователем.
3. **Защита Read All**: Запрашивает подтверждение пользователя перед тем, как отбросить любые несохраненные локальные правки.
4. **Изоляция телеметрии**: Телеметрия и периодический мониторинг обновляют таблицы состояния, но *никогда* не перезаписывают активные поля ввода на вкладке Config.
5. **Форматирование данных**: Поля L11/L16 принимают инженерные значения (физические величины). Все остальные числовые поля требуют ввода сырых шестнадцатеричных значений (RAW) с префиксом `0x`. Для команд `OPERATION` и `ON_OFF_CONFIG` используются пресеты под конкретные модели.

### Механизм предварительного просмотра и пакетной записи
- **Preview**: Локально готовит и структурирует изменения без инициализации ввода-вывода с устройством.
- **Пакетное применение (Batch write)**: Ограничивает пакетные операции строго командой `VOUT_COMMAND`. Движок сверяет базовые линии и проверяет точное совпадение считанных RAW-значений после записи.
- **Индивидуальное выполнение**: Команды `OPERATION`, `ON_OFF_CONFIG` и `WRITE_PROTECT` требуют раздельной записи и жесткой валидации чтения. Сбой при чтении или попытке записи аннулирует базовую линию, но сохраняет введенные пользователем данные для упрощения отладки.

## CSV, NVM и восстановление при отключении

### CSV и дампы регистров
- **Верификация контрольных сумм**: Загрузка внешнего CSV-файла требует наличия валидной контрольной суммы SHA-256. Несовпадающие или отсутствующие чексуммы отклоняются немедленно. Повторный экспорт сохраняет метаданные источника.
- **Профили дампов**: Перед записью дампа выборка записей и совместимость с целевым устройством проверяются на соответствие активному профилю. Функция Read Dump запрашивает только те регистры, которые разрешены текущей политикой общего доступа.
- **Ограничения записи**: Операция Write Dump не является слепым клонированием; импортированные записи не могут обойти ограничения записи, установленные на уровне PMBus.

### Энергонезависимая память (NVM)
- `Store NVM` и `Restore NVM` являются раздельными, явными операциями пользователя.
- Автоматический механизм отката или автоматическое сохранение в NVM после записи в RAM отсутствуют.
- Аппаратная валидация команд NVM рассматривается независимо от операций с RAM. Не следует циклически вызывать команды NVM для диагностики простых ошибок чтения.

### Алгоритм при отключении транспорта
При обнаружении отключения адаптера (например, преобразование ошибки `Errno 19` в исключение `TransportDisconnectedError`):
1. Циклы мониторинга телеметрии и сканирование адресов немедленно останавливаются и отменяются.
2. На соответствующей вкладке отображается статус `DISCONNECTED / STALE DATA`, а все элементы управления блокируются.
3. Межвкладочные защитные триггеры блокируют конфликтующие ручные действия на интерфейсах разных устройств.
4. Для восстановления: Переподключите аппаратный адаптер, нажмите кнопку **Refresh** для повторного перечисления шин, выберите целевую шину и запустите новое сканирование (**Scan**). Не продолжайте работу в старых вкладках.

## Отображение статусов и цветовая политика

Общие и подельние статусы декодируются с помощью модуля `gui/status_defs.py`.

- **LTM4673**: Реализовано специфичное декодирование для стандартных статусов, `STATUS_MFR_SPECIFIC` (команда `0x80`), `MFR_PADS` и `MFR_COMMON`. Значение `STATUS_MFR_SPECIFIC=0x18` расшифровывается как информационное состояние (целевое значение сервосистемы достигнуто, ЦАП подключен).
- **LTM4678**: Включено декодирование специфичных для производителя регистров `STATUS_MFR_SPECIFIC`, `MFR_PADS` и `MFR_COMMON` (с учетом инверсных сигналов активности).
- **LTM4677**: Специфичные регистры производителя отображаются в сыром (RAW) виде до завершения полной верификации. Стандартные статусы используют базовые определения PMBus.

### Цветовая индикация в GUI
Интерфейс применяет строгие правила цветового кодирования состояний (примечание: это логика интерфейса, а не прямое отражение аппаратных линий `ALERT`):
- 🟢 **Зеленый**: Текущее состояние в норме, ошибок и предупреждений не обнаружено.
- 🔵 **Синий**: Информационное состояние или дочерние метрики (например, маркеры готовности в `MFR_COMMON`).
- 🟡 **Желтый**: Регулятор зафиксировал состояние предупреждения (Warning).
- 🔴 **Красный**: Критическая ошибка (Fault) или физический сбой чтения (текст строки явно разграничивает эти ситуации).
- 🔘 **Серый**: Сырые данные регистров или неверифицированные профили декодирования.

## Аппаратное подключение и разводка

> ⚠️ **ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ ПО БЕЗОПАСНОСТИ**: Полностью отключайте питание силовой схемы перед изменением сигнальных линий или подключением к шине. Проверяйте модель, адрес, страницу и физические ограничения платы перед фиксацией любой записи. Не рекомендуется использовать общие или широковещательные адреса для тестирования единичных устройств.

### Типовая схема подключения FT232H к I2C

| Вывод / Сигнал FT232H | Целевое подключение | Примечания |
| :--- | :--- | :--- |
| **ADBUS0 / D0** | SCL (Serial Clock) | Требуется внешний подтягивающий резистор |
| **ADBUS1 / D1** | Выход SDA (SDA Output) | Должен быть объединен с D2 и линией SDA целевой платы |
| **ADBUS2 / D2** | Вход SDA (SDA Input) | Должен быть объединен с D1 и линией SDA целевой платы |
| **GND** | GND целевой платы | Общая «земля» для выравнивания потенциалов |

Убедитесь, что линии SCL и SDA оснащены подтягивающими резисторами (pull-up), подключенными к источнику напряжения, совместимому как с адаптером, так и с целевым модулем (в эталонном стенде использовался интерфейс 3.3 В; номинал резисторов должен соответствовать емкости шины). Не соединяйте силовые выходы питания адаптера с целевыми платами, имеющими собственный независимый источник питания.

## Зависимости и установка

### Системные требования
- **Python 3.13** (Рекомендуемая среда разработки; полная матрица совместимости минимальных версий находится в процессе формирования).
- **Tkinter** (Поставляется пакетным менеджером операционной системы или установщиком Python).
- **Системные библиотеки**: Для работы PyUSB и прямого взаимодействия с оборудованием требуется библиотека `libusb-1.0`.

### Установка
Создайте изолированное виртуальное окружение и установите необходимые привязки:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt hidapi
```
*(Или установите пакеты вручную: `pip install smbus2 pyusb pyftdi hidapi`).*

### Имена пакетов в различных дистрибутивах
- **Debian / Ubuntu**:
  ```bash
  sudo apt install python3-venv python3-tk libusb-1.0-0
  ```
- **openSUSE (Python 3.13)**:
  ```bash
  sudo zypper install python313-tk libusb-1_0-0
  ```

### Права доступа к USB в Linux (udev)
Чтобы работать с USB-адаптерами без использования `sudo`, создайте правило udev по пути `/etc/udev/rules.d/70-ltm-pmbus.rules`. Пример для CH341 (`1a86:5512`):
```text
SUBSYSTEM=="usb", ATTR{idVendor}="1a86", ATTR{idProduct}="5512", TAG+="uaccess"
```
Перезапустите правила системы и переподключите адаптер:
```bash
sudo udevadm control --reload-rules
```

## Варианты запуска и режимы работы

Всегда запускайте утилиту через окно терминала, чтобы диагностические сообщения при старте и логи консоли оставались видимыми.

### Аппаратный режим
```bash
python main.py
```
*При старте скрипт автоматически выполняет `dep_check.py` для верификации корректности окружения (Tkinter, PyUSB, PyFtdi, HIDAPI и libusb).*

### Демонстрационный режим / Симуляция
Если аппаратный адаптер недоступен, вы можете запустить режим демонстрации (только для чтения) с использованием синтетической телеметрии:
```bash
python main.py --demo
# или
python main.py --sim
```
*Примечание: В настоящее время проверка зависимостей драйверов требуется даже при загрузке в демонстрационном режиме. Компоненты симуляции находятся в процессе отладки и не должны использоваться для сквозной валидации карт устройств.*

## Структура проекта (Project layout)

```text
main.py                   # Точка входа в приложение и разбор флагов
dep_check.py              # Движок проверки зависимостей при старте
core/
    bus_factory.py        # Слой инициализации аппаратных адаптеров
    bus_scanner.py        # Сканирование шины I2C и временные диагностические циклы
    demo_device.py        # Демонстрация GUI (только для чтения) с использованием реальных профилей регистров устройств.
    dump_csv.py           # Обработчики импорта/экспорта CSV с защитой SHA-256
    i2c_backend.py        # Бэкенд I2C — smbus2, smbus
    pmbus_constants.py    # Стандартные команды PMBus и определения регистров
    pmbus_device.py       # Конечный автомат доступа к регистрам и валидация
    pmbus_formats.py      # Битовые парсеры форматов L11, L16 и RAW
    devices/
        base.py           # Базовые абстракции профилей устройств
        registry.py       # Регистрация и отслеживание профилей модулей
        ltm4673.py        # Карты регистров и специфичное декодирование LTM4673
        ltm4677.py        # Спецификации регистров LTM4677
        ltm4678.py        # Валидированные профили и параметры для LTM4678
    drivers/
        base_driver.py    # Структура интерфейса аппаратных драйверов
        ch341_i2c.py      # Транспортная обертка PyUSB для контроллеров CH341
        ftdi_i2c.py       # Транспортная обертка PyFtdi MPSSE для FTDI
        cp2112_i2c.py     # Реализация транспорта HIDAPI для Silicon Labs CP2112
gui/
    profiles/             # Визуальное размещение телеметрии и элементов Config
    app.py                # Главный контейнер окна Tkinter
    device_tab.py         # Многоканальный контейнер разметки устройства
    channel_frame.py      # Блоки отображения телеметрии для каждого канала
    config_notebook.py    # Интерактивный редактор регистров с валидацией
    register_tab.py       # Контроллер разметки нижнего уровня
    register_group.py     # Структурные группировки табличной сетки
    status_defs.py        # Политики цветов и карты декодирования регистров
sim/
    sim_bus.py            # Имитация шины I2C для тестирования без аппаратного обеспечения 
```
