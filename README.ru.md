# LTM PMBus Tool

Приложение на Python/Tkinter для чтения и настройки устройств управления питанием Analog Devices LTM и других устройств через PMBus. Поддерживает поиск устройств, телеметрию, редактирование настроек, расшифровку статусов и дампы регистров. Деморежим работает без адаптера.

## Поддержка и состояние проверки

Поддерживаются LTM4673 с четырьмя страницами каналов, LTM4677 с двумя и LTM4678 с двумя. Карта регистров устройства определяет доступность команд, область действия и права доступа. GUI-профиль определяет отображаемые поля телеметрии и настроек.

В проекте есть транспорты для CH341T, FT232H и CP2112. На LTM4678 адаптеры CH341T и FT232H проверены при поиске устройств, обычном чтении, мониторинге и переподключении. FT232H использует PyFtdi. CP2112 ещё требует аппаратной проверки. Поддержка модели не означает проверки всех её команд и операций.

Распределение доступных регистров в текущем Config проверено в деморежиме на отсутствие пропусков и дубликатов. Последняя версия индивидуального чтения и записи на оборудовании ещё не проверена. Испытания LTM4677 приостановлены из-за сомнений в исправности силовой части испытанной платы.

## Запуск

Установите зависимости Python и настройте доступ к USB для выбранного адаптера и операционной системы. Из корня проекта выполните:

```bash
python main.py
```

Для работы без оборудования выполните:

```bash
python main.py --demo
```

Деморежим создаёт имитируемые устройства поддерживаемых моделей. Start Monitor показывает меняющиеся синтетические значения, а не измерения или электрическую модель. Настройки доступны только для чтения; индивидуальное чтение и Read All позволяют просматривать данные. Деморежим не проверяет USB-обмен, запись, защиты или операции NVM.

## Интерфейс и доступ к регистрам

Для каждого устройства создаётся вкладка с общими областями и расположенными рядом панелями каналов. Телеметрия, настройки и статусы устройства и каналов разделены. Настройки Config сгруппированы во вкладках Output, Protection, Timing и Advanced. Глобальные регистры находятся только на уровне устройства, страничные – в редакторах каналов. Например, MFR_RETRY_DELAY глобален у LTM4673 и относится к каналу у LTM4677 и LTM4678.

Синяя стрелка читает регистр и заменяет значение поля, включая несохранённый ввод. Зелёная стрелка записывает значение после подтверждения и отображается только при разрешённой приложением записи. У регистров только для чтения её нет; в деморежиме запись недоступна. Текущий редактор включает читаемые скалярные регистры. Команды только для записи требуют отдельной реализации.

Стандартные поля L11 и L16 используют инженерные значения. Для остальных полей предусмотрен явно обозначенный сырой шестнадцатеричный ввод с префиксом `0x`. Нестандартные форматы производителя остаются сырыми, если для них нет отдельного редактора. Для OPERATION и ON_OFF_CONFIG предусмотрены списки значений, применимость которых ещё нужно проверить на оборудовании каждой модели. Неизвестные прочитанные значения отображаются как неизвестные.

Успешные запись и чтение не доказывают достижения требуемого физического состояния выхода. Общая проверка точного совпадения закодированного значения с прочитанным не выполняется. Write All отключена до реализации учёта изменённых полей, порядка записи и управляющих регистров, включая WRITE_PROTECT.

Start Monitor обновляет телеметрию и статусы, но не настройки. Отображение статусов различает аварии, предупреждения, информационные состояния, неизвестные значения и ошибки чтения там, где это поддерживается. Непроверенные статусы производителя могут оставаться в сыром виде.

## Отключение, дампы и NVM

Read All, мониторинг и индивидуальные операции Config обрабатывают обнаруженное отключение адаптера через вкладку устройства. Мониторинг останавливается, управление блокируется, данные помечаются как устаревшие. После подключения используйте Refresh и Scan. Refresh удаляет вкладки и закрывает кэшированные соединения перед повторным поиском. Отдельные обработчики NVM, дампов и устаревших элементов интерфейса пока не охвачены этим механизмом единообразно.

Чтение дампа, импорт и экспорт CSV, запись дампа, сохранение и восстановление NVM работают отдельно от Config. Импорт CSV не подтверждает пригодность дампа для конкретного устройства или платы. Запись дампов и операции NVM требуют отдельных аппаратных испытаний; не используйте их для первой проверки записи после обновления.

Ближайшая аппаратная проверка охватывает индивидуальное чтение и Read All, разделение глобальных и страничных настроек, безопасную запись в RAM с чтением и восстановлением исходного значения, ограничения ввода и отключение адаптера во время работы. NVM и запись дампов в этот этап не входят.

## Структура проекта

- `core/drivers` содержит поддержку моделей устройств.
- `gui/profiles` задаёт телеметрию и размещение настроек.
- `gui/config_notebook.py` реализует общий редактор Config.
- `gui/channel_frame.py` реализует панели каналов.
- `gui/device_tab.py` реализует представление устройства и мониторинг.
- `gui/status_defs.py` реализует отображение статусов.

## Добавление USB-to-I2C адаптера

1. Изучите существующий транспорт, `core/bus_factory.py`, обнаружение адаптеров в `gui/app.py` и вызовы в `core/pmbus_device.py`. Не добавляйте особенности адаптера в драйверы устройств.
2. Реализуйте нужные байтовые, словные, блочные транзакции и команды без данных. Проверьте порядок байтов, длины блоков, repeated START, STOP, ACK/NACK, растяжение тактового сигнала, частоту шины, формирование SMBus-транзакций и работу PEC.
3. Передавайте отключение и ошибки обмена распознаваемыми исключениями. Отличайте NACK адреса от отключения, проверяйте длину ответа и не подменяйте ошибки вымышленными значениями. Флаги возможностей должны соответствовать фактическому поведению.
4. Соблюдайте схему общего использования шины, кэширования, блокировок и освобождения ресурсов. Не закрывайте общий адаптер из-за ошибки отдельного устройства и не выполняйте непроверенные сбросы или записи при открытии.
5. Зарегистрируйте создание и обнаружение адаптера. Идентификаторы должны различать подключённые экземпляры; отсутствие необязательной библиотеки не должно мешать другим транспортам и деморежиму.
6. Проверьте поиск и повторное чтение на известном устройстве, затем отключение во время поиска, Read All и мониторинга. После подключения проверьте Refresh, Scan, освобождение кэшированных соединений и работу нескольких устройств на одной шине.
7. Отдельно проверьте запись безопасного параметра RAM, чтение результата и восстановление исходного значения. NVM и запись дампов оставьте для следующего этапа. Опишите зависимости, требования к USB-драйверу, поддерживаемые транзакции и ограничения.

## Добавление устройства PMBus

1. Соберите документацию точной модели или версии прошивки. Определите адреса, число каналов, поведение PAGE, безопасные команды идентификации, типы транзакций, форматы и семантику ошибок.
2. Добавьте точную идентификацию и выбор драйвера в `core/drivers`. При необходимости измените `core/pmbus_device.py` или `core/bus_scanner.py`; не отправляйте неподдерживаемые команды идентификации безусловно.
3. Опишите код, имя, размер транзакции, формат, область действия и раздельные права чтения и записи каждой поддерживаемой команды. Не превращайте команды без данных, блочные операции, NVM и запись по общему адресу в обычные скалярные поля.
4. Реализуйте преобразования по документации, включая поведение VOUT_MODE. Проверяйте кодирование до разрешения инженерной записи. Неподдерживаемые форматы оставляйте явно сырыми.
5. Зарегистрируйте профиль в `gui/profiles` с глобальной и канальной телеметрией и размещением настроек. Доступность, область действия и права определяет карта регистров, а не GUI.
6. Добавьте определения статусов модели в `gui/status_defs.py`. Не заимствуйте непроверенную расшифровку регистров производителя у другой модели.
7. Добавьте демоустройство и проверьте число страниц, выбор профиля, размещение полей и обработку устаревших данных. Деморежим не подтверждает аппаратную совместимость.
8. Проверяйте оборудование поэтапно: безопасное чтение, контролируемую запись в RAM с восстановлением, затем отдельно реакции на ошибки, NVM и запись дампов. Различайте реализованные, проверенные в демо и подтверждённые на оборудовании операции.

## Безопасность

Запись регистров может изменить работу системы питания. Перед ней проверьте документацию, ограничения платы, адрес и модель устройства, страницу и назначение параметра. Сохраните исходное значение и используйте контролируемый стенд. Не записывайте по общим или широковещательным адресам при проверке отдельного устройства и не сохраняйте экспериментальные настройки в NVM до проверки их поведения.
